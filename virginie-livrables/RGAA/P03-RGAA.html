RGAA-7-1-SCRIPT-ARIA-HIDDEN-003 - Composant scripté visible mais masqué aux technologies d’assistance

NC_CONFIRMEE Bloquant Critère 7.1 Test 7.1.1

Sélecteur : #search-input

Observation : Contrôle scripté focalisé à la tabulation 10 sous aria-hidden=true

  • Le composant scripté visible ne restitue pas correctement ce contrôle aux API d’accessibilité.
Comparer le code observé et attendu

Preuve observée - KEYBOARD_TRACE

<input class="fr-input" name="query" aria-describedby="search-input-messages" placeholder="Rechercher" id="search-input" type="search" style="">

Ancêtre masqué:
<form action="/recherche" method="get" class="fr-search-bar" id="search" role="search" aria-hidden="true">
								<label class="fr-label" for="search-input">
									Rechercher
								</label>
								<input class="fr-input" name="query" aria-describedby="search-input-messages" placeholder="Rechercher" id="search-input" type="search" style="">
								<div class="fr-messages-group" id="search-input-messages" aria-live="polite"></div>
								<button title="Rechercher" type="submit" id="search-btn" class="fr-btn">Rechercher</button>
							</form>

Résultat attendu

<div role="dialog"><form role="search">…</form></div>

Origine de la preuve : KEYBOARD_TRACE. Elle ne constitue pas du code source applicatif.

Impact : Le champ et le bouton visibles peuvent perdre leur nom, leur rôle et leur valeur pour une technologie d’assistance.

Source : RGAA 4.1.2 - test 7.1.1

Recommandation : Retirer aria-hidden avant l’ouverture et avant tout déplacement du focus vers la recherche.

Contre-test : Ouvrir le composant au clavier puis contrôler simultanément le focus, le DOM et l’arbre d’accessibilité.

Qualification : La recherche pilotée par script devient visible, mais form#search conserve aria-hidden=true et ses contrôles ne sont plus correctement exposés aux API d’accessibilité.
